This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
# Run the server
go run main.go

# Build the binary
go build -o chirpy .

# Apply database migrations
goose postgres "postgres://sinedviper:@localhost:5432/chirpy" up

# Roll back last migration
goose postgres "postgres://sinedviper:@localhost:5432/chirpy" down

# Regenerate database code from SQL queries (after modifying sql/queries/ or sql/schema/)
sqlc generate
```

## Architecture

This is a single-file Go HTTP API (`main.go`) for a Twitter-like service. All route handlers are defined inline in `main()` with no routing framework — standard library `net/http` only.

**Key configuration** is loaded from `.env` via `godotenv`:
- `DB_URL` — PostgreSQL connection string
- `PLATFORM` — set to `"dev"` to enable destructive admin endpoints

**`apiConfig`** is the central state struct holding an atomic hit counter and the `*database.Queries` handle used by all handlers.

### Database layer

The DB layer is fully code-generated by [sqlc](https://sqlc.dev/):
- SQL schemas live in `sql/schema/` (migrations use [goose](https://github.com/pressly/goose) syntax with `-- +goose Up/Down` comments)
- Named queries live in `sql/queries/`
- Generated Go code lives in `internal/database/` — **do not edit these files manually**

After adding or modifying queries in `sql/queries/` or schema in `sql/schema/`, run `sqlc generate` to regenerate `internal/database/`.

### API endpoints

| Method | Path | Description |
|--------|------|-------------|
| GET | `/api/healthz` | Health check |
| GET | `/admin/metrics` | Hit counter (HTML) |
| POST | `/admin/reset` | Reset hits + delete all users (dev only) |
| POST | `/api/users` | Create user |
| POST | `/api/chirps` | Create chirp (max 140 chars, filters profanity) |
| GET | `/api/chirps` | List all chirps |
| GET | `/api/chirps/{chirpID}` | Get single chirp |

The `argon2id` and `golang.org/x/crypto` packages are already in `go.mod` for password hashing — the `003_users_add_password.sql` migration adds the `hashed_password` column.
